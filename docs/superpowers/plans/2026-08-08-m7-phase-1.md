# M7 Phase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete the Phase 1 M7 golden-slice, resilience, and performance gate using a repository-level `tools/phase1` harness and record reproducible exit evidence.

**Architecture:** Keep production packages unchanged unless a failing M7 scenario exposes a concrete Phase 1 defect. Add typed scenario fixtures, replay/projection assertions, real MCP observation integration tests, and benchmark orchestration under `tools/phase1`. Use public package exports, temporary Git repositories/worktrees, temporary SQLite stores, and deterministic JSON evidence.

**Tech Stack:** TypeScript 5.7, Node.js >=22.5, `tsx`, `node:test`, Node `node:sqlite`, temporary Git repositories/worktrees, SHA-256 digests, and the existing Phase 0 workload definitions.

## Global Constraints

- M7 remains observation-only and report-only; stored coordination output is limited to `record` and gateway behavior remains `allow`.
- The closed Phase 1 event set remains authoritative: `tool.requested`, `tool.completed`, `file.read`, `file.changed`, `symbol.read`, `symbol.changed`, `task.completed`, `dependency.changed`, and `attribution.corrected`.
- Do not add Phase 2 detectors, findings, policy decisions, validity behavior, `delay`, `reject`, overlap, stale, or revalidation commands.
- Use the public exports of `@patchmesh/protocol`, `@patchmesh/storage`, `@patchmesh/observation`, `@patchmesh/adapters`, `@patchmesh/query`, and `@patchmesh/daemon` from the harness.
- Do not add a runtime adapter, database migration, network listener, graph database, distributed queue, or external benchmark service.
- Every temporary repository, worktree, database, child process, and abort signal must be cleaned up in `finally` blocks.
- Never persist secrets, full environment values, raw command credentials, or hidden model reasoning.
- Preserve strict TypeScript settings, immutable event storage, rebuildable projections, and deterministic ordering.
- Do not commit changes unless the user explicitly requests a commit; leave the implementation and evidence in the worktree for review.
